# Generative Agents：核心笔记


## 1. 它解决什么问题？

智能体要在很长时间里保持一致、可信的行为，但经历会不断增长，无法全部放进上下文。论文要解决两件事：

1. **记忆怎么存**：把感知、反思、计划统一存进“记忆流”；
2. **记忆怎么取**：从大量记录中挑出少数相关记忆，送进有限上下文，条件化下一步行为。

目标为行为可信度，不是问答正确率。反思机制解决的是“只有原始观察、不会归纳”的问题。

## 2. 核心办法是什么？

### 2.1 总架构

```text
                 ┌─────────────── 记忆流 Memory Stream ───────────────┐
                 │  观察 observation │ 反思 reflection │ 计划 plan    │
                 └────────────────────────────────────────────────────┘
  感知 Perceive ──写入──▶        │ 检索 Retrieve（相关性+近因性+重要性）
                                 ▼
                          取出的记忆 Retrieved Memories
                                 │
              ┌──────────────────┼──────────────────┐
              ▼                  ▼                  ▼
          决定行动 Act       生成计划 Plan      生成反思 Reflect
              │                  │                  │
              └──────────── 写回记忆流 ◀────────────┘
```

感知先写进记忆流；检索从流里取记忆；取出的记忆用于行动、计划和反思；计划和反思又写回同一条流。

三类记忆都存进记忆流，并共享同一个检索池：

| 类型 | 是什么 | 例子 |
|---|---|---|
| 观察 | 直接感知到的事件 | “Klaus 在读一篇关于定量的论文” |
| 反思 | 从多条记忆归纳出的高层结论 | “Klaus 非常投入研究” |
| 计划 | 未来一段时间的行为安排 | “下午 1 点在图书馆读论文” |

### 2.2 记忆流

每条记忆至少包含：

```text
description          自然语言描述
created_at           创建时间（游戏时间）
last_accessed_at     最近一次被检索/访问的时间
importance           写入时由 LLM 打的 1–10 分
```

- 以自然语言存储，便于直接拼进 prompt，也便于用语言模型打分。
- 论文没有描述删除机制；可理解为持续追加的记录。“追加”是由架构推出，不是原文明说。
- 检索时对每条记忆算：

```text
score = relevance + recency + importance
relevance  = cos(query, memory)
recency    = 0.995 ** (当前游戏小时 - 最近访问游戏小时)
importance = 1–10
```

三项各自 min-max 到 [0,1]，权重均为 1，取高分直到填满上下文窗口。**反思、观察、计划在这个公式里同权竞争，没有特殊通道。**

### 2.3 反思机制

#### 为什么需要

原始观察太碎，不足以回答需要归纳的问题。论文 §4.2 的例子：问 Klaus“你愿意和谁共度时光？”

- 只有观察时，系统按互动次数选 Wolfgang；
- 但 Klaus 和 Wolfgang 只是常擦肩而过；
- 多条“Klaus 读论文、查资料、和馆员讨论”的观察，可归纳为“Klaus 投入研究”，从而选中同样做研究的 Maria。

反思的功能：**把碎片事实压缩成高层判断，让有限上下文装得下“这个人是什么样”的信息。**

#### 什么时候反思

论文写的是：当智能体感知到的**最近事件的重要性分数之和超过阈值**时触发反思；实现中阈值取 **150**，实际大约**每天 2–3 次**。

- 触发依据是**重要性累计**，不是固定时间；
- 低重要性琐事累积慢，重要事件会加快触发；
- 计数器是否在反思后清零、反思本身是否计入下次累计，论文**未说明**。

#### 反思怎么生成

```text
① 取最近 100 条记忆记录
        ↓
② 让 LLM 生成 3 个“最值得回答的高层问题”
        ↓
③ 对每个问题，用普通检索函数取相关记忆（可包含旧反思）
        ↓
④ 让 LLM 输出 5 条高层洞察，并标注依据编号
        ↓
⑤ 作为“反思”写回记忆流，保留指向被引用记录的指针
```

第 ② 步的提示词大意是：“仅根据这些陈述，我们能提出哪 3 个最显著的高层问题？”

第 ④ 步要求格式类似：

```text
Klaus is dedicated to his research (because of 1, 2, 8, 15)
```

因此反思不是自由摘要，而是**带证据指针的归纳**：能回溯到具体观察。

#### 递归与反思树

反思可以引用观察，也可以引用之前的反思。于是形成一棵树（论文 Fig. 7）：

```text
                    [反思] Klaus 非常投入研究
                    /            |            \
      [反思] 花很多时间阅读   [反思] 关注研究进展   [反思] 与同行讨论
        /        \              |                  /        \
 [观察]读论文  [观察]查资料  [观察]做笔记      [观察]问馆员  [观察]讨论
```

- 叶节点：原始观察；
- 越往上：越抽象的高层结论；
- “递归”指反思可以被再次反思，**不是无限循环**；触发仍由重要性阈值控制；
- 最大深度、是否去重、反思之间冲突如何处理，论文**未说明**。

#### 反思存在哪、怎么进入回答

- 反思**不是**单独的数据库，也**不是**写进 system prompt 的固定人设；它作为一条普通记忆写回记忆流。
- 每次行动/对话前，检索函数对观察、反思、计划**统一打分**，取 top 填上下文。
- 被选中的反思文本进入当次 LLM prompt 的“相关记忆”部分，模型据此决定行动或生成对话。
- 计划也写回记忆流，之后可能再被检索，形成二次影响。

一条链路概括：

```text
反思写回 → 与观察同池 → 三因子检索 → 进入上下文 → 条件化行动/对话
```

#### 对行为的影响

论文给了两个直接例子：

1. **选人**：Klaus 被问愿意和谁共度时光；反思“投入研究”使模型选择 Maria，而不是互动最多的 Wolfgang（§4.2）。
2. **送礼**：Maria 被问送 Wolfgang 什么生日礼物；没有反思时她答不知道，有反思时她根据“Wolfgang 对数学音乐作曲感兴趣”提出乐谱或音乐软件（§6.5.3）。

机制上，反思把“多条零散观察（生成时最多读取最近 100 条）”压缩成“1 条高层判断 + 证据指针”，让模型在有限上下文里获得更概括的信息，因此行为更一致。代价是：**反思是模型推断，可能概括错、过度推广，或被后续检索反复放大。**

## 3. 哪些参数固定、哪些学习得到、哪些未说明？

| 类别 | 内容 |
|---|---|
| 固定 | 近因衰减底数 0.995；三项权重均为 1；min-max 归一化；重要性 1–10；反思触发阈值 150；取最近 100 条；生成 3 个问题；每个问题 5 条洞察；实现中约每天 2–3 次反思 |
| 学习得到 | **无**。重要性由 LLM 在写入时打分；反思由 LLM 生成；没有训练排序权重 |
| 未说明 | 检索取多少条 K；嵌入模型；查询如何构造；`last_accessed` 何时更新；反思的重要性如何打分；反思去重、最大深度、冲突处理；提取/反思的完整提示词；反思是否计入下次触发累计 |

## 4. 用什么题目和指标验证？

两层验证。

**受控评测（§6）**：100 名评估者，对同一智能体的回答按可信度排序；问题分五类：自我知识、记忆、计划、反应、反思。用 TrueSkill 汇总：

| 条件 | TrueSkill μ |
|---|---|
| 完整架构 | **29.89 ± 0.72** |
| 去掉反思 | 26.88 ± 0.69 |
| 去掉反思和计划 | 25.64 ± 0.68 |
| 去掉记忆、计划、反思 | 21.21 ± 0.70 |
| 人类众包作者 | 22.95 ± 0.69 |

结论：去掉反思会降低可信度，说明反思对需要归纳的回答有贡献；但这是**行为可信度**，不是检索准确率。

**端到端小镇模拟（§7）**：25 个智能体跑两天，观察信息扩散、关系形成与协调行为。属于涌现行为观察，不是受控指标。

**没有** Recall、MRR、NDCG 等证据级检索指标；无法据此判断“反思是否让正确证据排得更前”。

## 5. 没解决什么，与本课题是否相关？

- **反思可能错**：论文 §6.5.2 报告智能体会“润色/编造”细节，例如 Isabella 说 Sam 将发表演讲，但两人并未讨论过；反思会把这类推断固化。
- **反思没有有效期**：没有 `valid_from / valid_to`；旧反思可能一直有效、一直被检索。
- **反思只有证据指针，没有校验**：能回溯到观察，但不会检查观察是否过时或互相矛盾。
- **规模变大后检索变难**：§7.2 指出记忆越来越多时，检索相关信息和选择合适行动地点都会变困难。
- **近因 ≠ 时效，重要 ≠ 任务有用**：反思提高了“重要性/概括性”，但仍不回答“这条记忆对当前任务是否适用”。
- **与课题相关**：反思是“语义不明显但影响决策”的记忆的典型来源，可对应 RQ3 的任务相关性；但排序时必须把它当**派生证据**，保留来源指针，区分观察与反思，并处理反思冲突和时效。

## 6. 复现、借鉴、比较，还是仅作背景？

**比较 + 借鉴。** 检索三因子作为 B2 基线；反思机制不作为排序基线，而作为“派生记忆如何进入候选池”的设计参考。当前不复现小镇、地图和角色生活。原论文的 importance 由 LLM 在写入时打分。
**决策：这篇论文对本课题的用途是——作为“相关性 + 近因性 + 重要性”三因子基线（B2），并把“反思=带证据指针的派生记忆”作为任务相关性候选的来源设计参考，而不是完整复现其智能体系统。**
