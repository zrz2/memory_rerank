# 实验协议 v1：BGE-M3 + DeepSeek 候选重排小试验

冻结日期：2026-11-13。范围为原有六个公开问题，不增加或根据结果挑选问题，不调参，不当作正式测试集。用户授权本轮 API 最多5元。

1. 用固定版本 BGE-M3 对完整可见历史轮次召回。200 token 窗口、160步长，轮次取最高窗口相似度。沿用原六题，旧 E5 文件不覆盖。
2. 每题取纯语义前20轮作为共享候选。所有重排方法只在同一池里竞争；额外报告整个历史上的语义+近因性对照，必须标记候选范围不同。
3. 主要方法：semantic_top20、semantic_recency_top20、ga_importance_top20、deepseek_rerank_top20。GA式重排以三个归一化因子等权相加，decay=0.995/小时；last_accessed仅以会话时间代理。
4. API读取每条记忆固定前1600字符，逐条记录截断；importance提示不含当前问题，评分1–10。DeepSeek重排读取问题、问题时间、记忆时间和相同文本视图。完整向量召回与截断后的LLM视图不同，这是明确的工程限制，不隐藏。importance不是原论文同一模型／逐条提示／完整记忆打分，命名为GA式候选重排改编。
5. 数据原始ID含answer前缀，不得输入模型。发送时重新随机打乱并替换为M001等无语义别名；不发送正确答案、has_answer、gold_ids、answer_session_ids、oracle标签。相同候选顺序用于两次API请求。模型输出必须覆盖全部合法别名，无重复，importance必须为1–10整数，重排必须为完整排列；失败不静默回退，不按有利结果重试。
6. importance提示只评估用户长期值得记住的重要程度；不把“对当前问题相关”混成importance。按批次打分仍可能有候选集合影响，不能视为彻底独立的写入评分。
7. 只在评价端使用has_answer，报告全体gold作为分母的Recall@K、MRR@K、NDCG@K、全部已标证据覆盖率，以及候选Recall@20、逐题差值。未标注轮次可能仍有可用信息，且不保证所有标注都为必要证据，所以全部已标证据覆盖率不是官方答案正确率。
8. 12次请求封顶（每题2次），每次输出最多1200 tokens。不自动重试。缓存键包括完整请求和LLM配置；请求前持久化预算预留，网络失败也不回收预留，以防重复扣费。预算按每百万输入10元、输出30元预留，高于核验当天官方Flash与Pro高峰价格。输入以UTF-8字节数加1024的保守上界估算。总预留超过5元则拒绝继续。
9. 保存原始回复、模型身份、token用量、耗时、缓存状态、代码Git版本、数据hash、配置、逐题排名。实际费用只能从平台账单确认，报告token按公开高峰价格估算，不能把估算说成真实扣款。
10. 此阶段不训练新方法、不声称优于GA原文、不做官方QA judge，不把LLM重排叫作Cross-Encoder。后续仍要加入固定开源Cross-Encoder、独立dev/test、自动时间有效性与任务状态实验。
